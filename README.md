# 🚀 FEATURED SYSTEMS & ARCHITECTURES

## 🔷 NexaRAG — Context Orchestration Platform
<p align="center">
  <img src="./assets/nexarag-architecture.gif" width="100%" alt="NexaRAG Architecture Pipeline"/>
</p>

* **Architecture:** Hybrid BM25 + FAISS retrieval, Cross-Encoder reranking, Context Budgeting (6,000-token dynamic window), and 3-tier NVIDIA NeMo guardrails.
* **Context Engine:** Multi-strategy routing across **RAG** (Retrieval), **CAG** (Cache-Augmented), and **MAG** (Memory-Augmented) synthesis.
* **Stack:** FastAPI, LangChain, FAISS, PostgreSQL, Docker, React.
* 🔗 **[Explore NexaRAG Repository →](https://github.com/Livesh-L-28/Nexa_RAG)**

---

## 🛡️ LLMFirewall — Defensive AI Security Layer
* **Architecture:** Runtime policy enforcement, jailbreak detection, prompt injection mitigation, and sensitive PII masking.
* **Benchmarks:** Sub-45ms inference latency overhead, 98.4% detection on OWASP Top 10 for LLMs benchmark datasets.
* **Stack:** Python 3.11+, PyRight, MkDocs, Docker, Automated CI/CD.
* 🔗 **[Explore LLMFirewall Repository →](https://github.com/Livesh-L-28/LLMFirewall)**

---

## 🧬 MedicalTransformerLM — Domain-Specific Medical LLM + RAG
<p align="center">
  <img src="./assets/medical-llm-pipeline.gif" width="100%" alt="Medical Transformer LM Pipeline"/>
</p>

* **Architecture:** Custom ~110M parameter medical transformer trained with PyTorch, integrated with OpenBioLLM and medical acronym expansion.
* **Grounded Synthesis:** Hybrid retrieval with citation validation against clinical corpora.
* 🔗 **[Explore Medical LLM Repository →](https://github.com/Livesh-L-28/MEDICAL_LLM)**

---

## 👁️ AI Visual Memory System

# 🧩 CORE ENGINEERING PRINCIPLES

```text
01. Build systems, not isolated models.
02. Ground AI outputs with reliable retrieval and context budgeting.
03. Treat AI security as an architectural runtime layer.
04. Measure before optimizing (profile latency, token budget, and false positive rates).
05. Automate verification: if it's not tested in CI, it's broken.
06. Design for reproducibility with lockfiles, containers, and explicit schemas.
07. Keep systems modular, observable, and observable under failure.
08. Ship production-oriented engineering over disposable notebooks.
```
